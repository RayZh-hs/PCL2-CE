# I18N Implementation Checklist

Based on `docs/I28NImplementationGuide.md`.

## Phase 1: Infrastructure (Core)
- [x] Create `PCL.Core.App.I18nService` class.
- [x] Implement JSON language file loading logic.
- [x] Add `Language` property to `PCL.Core.App.Config`.
- [x] Create `Languages/` directory structure.
- [x] Create initial `zh-CN.json` and `en-US.json` files.

## Phase 2: UI Integration (Settings)
- [x] Add Language ComboBox to `PageSetupSystem.xaml` (Settings -> General).
- [x] Implement `ComboLanguage_SelectionChanged` handler in `PageSetupSystem.xaml.vb`.
- [x] Bind ComboBox selection to `Config.Language`.
- [ ] Implement "Restart to Apply" notification when language changes.

## Phase 3: First Launch Experience
- [ ] Detect if `Config.Language` is empty on startup (`Application.xaml.vb`).
- [ ] Create a dedicated Language Selection Dialog/Window for first launch.
- [ ] Prevent main window loading until language is selected.
- [ ] Save selected language to `Config.Language`.

## Phase 4: XAML Integration (Advanced)
- [ ] Create a XAML MarkupExtension (e.g., `TranslateExtension` or `{i18n:Translate}`) to allow direct usage in XAML.
  - Example: `<TextBlock Text="{i18n:Translate Key='LaunchButton'}" />`
- [ ] Ensure dynamic updating of UI elements when language changes at runtime (optional, restart is easier).

## Phase 5: Content & Translation
- [ ] Audit codebase for hardcoded strings.
- [ ] Extract strings to `zh-CN.json`.
- [ ] Provide translations for `en-US.json`.
- [ ] (Optional) Add support for other languages (e.g., `fr-FR`, `ru-RU`).

## Phase 6: Testing & Polish
- [ ] Verify language persistence after restart.
- [ ] Test fallback behavior if a key is missing in the selected language.
- [ ] Test behavior if a language file is missing or corrupt.
